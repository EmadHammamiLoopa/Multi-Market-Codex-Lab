D6B is not rerun, reclassified as PASS, or relaxed.

## Why D6R exists

The frozen hftbacktest 2.4.4 Tardis converter allocates one whole-day
event buffer and also reads complete CSV files with Polars.

January alone requires about 3.795 GiB for mandatory event allocation
before the additional dataframe, sorting, and temporary-array cost.

The frozen D6B safety requirement was about 15.18 GiB available memory,
while the execution environment had about 10.50 GiB available.

Later development days are substantially larger.

Therefore the whole-day in-memory path is resource-infeasible for the
frozen environment.

This is an engineering execution-path amendment only.

It does not change:

- market data;
- data dates;
- fees;
- latency assumptions;
- policies;
- strategy parameters;
- statistical gates;
- economic gates.

## Exact base-event semantics

Input order remains:

1. trades
2. incremental_book_L2

Timestamps remain microseconds multiplied by 1000 to nanoseconds.

`base_latency=0`.

`snapshot_mode="process"`.

Zero-quantity depth updates remain valid delete events.

Snapshot state must survive chunk boundaries.

When a snapshot batch closes, output ordering must remain exactly:

1. bid clear;
2. bid snapshot rows;
3. ask clear;
4. ask snapshot rows;
5. current regular depth row.

The clear event uses the first snapshot event timestamp for that side,
the last snapshot price for that side, and quantity zero.

## Stable original sequence

Each converted base event receives a temporary monotonic `source_seq`.

The sequence represents the exact upstream base-event creation order:

- every converted trade event first;
- then every converted depth event.

`source_seq` is temporary metadata only and is never written into the
final hftbacktest event dtype.

It exists to reproduce NumPy stable mergesort behavior exactly when
timestamps tie.

## Bounded reading

Production raw chunk size is frozen at:

`500,000 rows`

Tests may intentionally use smaller chunk sizes to force chunk-boundary
conditions.

Whole-day `pl.read_csv()` is prohibited.

Whole-day event-array preallocation is prohibited.

## External stable sorting

Temporary records contain the event fields plus `source_seq`.

Two globally ordered logical streams are produced:

Exchange stream:

`(exch_ts, source_seq)`

Local stream:

`(local_ts, source_seq)`

This reproduces the stable order generated by upstream mergesort.

## Local timestamp correction

D5B already established nonnegative raw feed latency for every frozen
row and D6 freezes `base_latency=0`.

Therefore the bounded implementation must treat
`correct_local_timestamp()` as an identity operation and fail closed if
negative latency is encountered.

It may not silently repair such data.

## Final event ordering

The final merge must reproduce the frozen upstream
`correct_event_order()` branch logic exactly.

When the exchange-stream and local-stream heads refer to the same exact
timestamp pair, they must also refer to the same `source_seq`.

The event is then emitted with both EXCH_EVENT and LOCAL_EVENT flags.

Otherwise the exact upstream exchange-only/local-only branch logic is
used.

## Final output

The final converted day is a disk-backed NumPy `.npy` event array using
the exact hftbacktest `event_dtype`.

The final file contains no `source_seq`.

A two-pass final merge is required:

1. first pass determines exact output row count;
2. second pass creates and fills an exact-size disk-backed array.

The final file itself is scratch data and is not committed to Git.

Its SHA-256, shape, dtype identity, and validation result are retained
as evidence.

## Mandatory synthetic oracle parity

Before any full-day bounded conversion, the new converter must match the
frozen upstream Tardis converter field-for-field.

The fixture must include:

- buy and sell trades;
- bid and ask depth;
- zero-quantity delete;
- SOD snapshot;
- snapshot crossing a chunk boundary;
- duplicate timestamps;
- exchange timestamp reversal;
- nondecreasing local timestamps;
- equal exchange/local timestamp pair.

Parity must be tested using chunk sizes:

`1, 2, 3, 7`

Comparison is exact fieldwise equality with NaN treated as equal.

## Mandatory real-data parity

After synthetic parity, a fixed real slice is used:

- BTCUSDT
- 2026-01-01
- local-time window `[00:00:00, 00:10:00)`

The window is fixed by time only.

No policy result or PnL is consulted.

Both the frozen upstream converter and bounded converter receive the
same temporary slice.

The fixed slice must terminate outside a snapshot batch.

Their final event arrays must match field-for-field.

## Resource gate before full day

A full January day remains unauthorized until:

1. implementation is frozen;
2. synthetic parity is frozen GREEN;
3. fixed 10-minute real parity is frozen GREEN;
4. a resource preflight is frozen GREEN.

The later memory rule is:

`MemAvailable >= 4 × peak process RSS observed on the fixed real parity slice`

Swap does not count.

The later scratch-disk rule is:

`free scratch bytes >= 6 × base event buffer bytes`
